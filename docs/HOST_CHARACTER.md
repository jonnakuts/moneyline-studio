# Host character

A recurring, original, code-drawn character gives the channel a personality and makes it clearly *ours*
(not an interchangeable faceless channel). The host **supports** the data; it never replaces it.

## Status

Design not chosen yet. Before the first video's Stage 5, propose 3 concepts (sketched as SVG in a model
sheet) and let the owner pick. Directions to explore:

1. **A coin with a face:** a slightly worn coin; expressions via engraved-style eyes and mouth; can roll,
   spin, and stack.
2. **A receipt character:** a curled thermal receipt; its printed lines double as expressions; tears and
   crumples when shocked.
3. **A minimal analyst figure:** a simple geometric figure with glasses and a tie made from the Money Line.

Constraints: original (no resemblance to any existing mascot or brand character), readable as a small
corner overlay, cheap to animate, fits the LEDGER/RECEIPT worlds and the color tokens.

## How it's built (zero cost, no AI images)

We borrow the **approach** from `kevinbadi/claude-codes-influencers` (MIT), not its image pipeline:

- **Art is drawn in code**, like that repo's code-drawn rigs: SVG parts generated by a script in
  `assets/host/`. No uploaded picture, no image model, no paid API (we skip that repo's `create --image`
  route, which calls a paid API).
- **Rig parts:** body, eyes (open / half / closed / wide), brows, mouth shapes, arms or equivalent, plus
  2–4 poses (idle, point, shrug, shock).
- **Mouth shapes:** Rhubarb's set: A, B, C, D, E, F (basic) + G, H, X (extended). One SVG per shape, all
  sharing one anchor point.
- **Lip-sync:** run **Rhubarb Lip Sync** (free, CPU, Windows binary) on the frozen narration (or the
  host's lines only), passing the known text as dialog to improve accuracy. Save `03-voice/visemes.json`
  (`mouthCues: [{start, end, value}]`). This is a derived timing file: frozen with Gate C.
- **In Remotion:** a `HostOverlay` component reads `visemes.json`, picks the mouth for the current frame,
  blinks on a seeded schedule, and plays poses defined in the screenplay.

## How it's used

- **Screen time:** about 10–15% of a long video. Not in every scene.
- **Jobs:** delivers or reacts to the cold-open hook; reacts to big reveals ("wait, *how* much?"); bridges
  sections; points at a chart element; the outro.
- **Placement:** corner overlay in long-form (respect safe zones), larger or full-frame in Shorts.
- **Voice:** same narration voice (the host *is* the narrator). Lines the host speaks on camera are marked
  `[HOST]` in `script.md`.
- **Interaction:** the host should physically interact with the world (lean on a bar chart, get hit by a
  falling coin, pull the Money Line), not just float beside it.

## Consistency

Keep the canonical rig in `assets/host/` with a `model-sheet.svg` showing every pose and mouth shape.
Any change to the rig is a decision recorded in `docs/DECISIONS.md`.
